BrokerControl360

Spécification fonctionnelle et stratégie de génération d'un historique BVMAC 2026 pour une démonstration
Positionnement. BrokerControl360 est une plateforme de contrôle et de pilotage pour les sociétés de bourse agréées par la COSUMAF. Elle complète un système de négociation ou de conservation ; elle ne cherche pas à les remplacer.

3. Données BVMAC disponibles

Le dossier json contient 19 bulletins BVMAC couvrant les séances du 1er au 25 septembre 2026. Chaque bulletin contient 7 actions, 31 obligations, l'indice BVMAC All Share, les volumes, la capitalisation, les encours obligataires et des lignes OPCVM.

Les principales actions présentes sont SEMC, SAFACAM, SOCAPALM, La Régionale, BANGE, SCG-Re et BGFI Holding Corporation.

Point important: le statut NC apparaît fréquemment. Une absence de transaction ne signifie pas nécessairement une variation de prix. Les volumes nuls ne doivent donc pas être remplacés par des valeurs inventées.

4. Limite de l'historique annuel

Les données de janvier à août 2026 ne peuvent pas être réellement interpolées puisque les observations disponibles commencent en septembre. Il faut distinguer clairement :

StatutSignificationUtilisation
OBSERVEDValeur directement extraite d'un bulletin BVMAC.Calculs et reporting de référence.
INTERPOLATEDValeur calculée entre deux observations réelles.Graphiques et démonstrations, avec avertissement.
SIMULATEDValeur générée pour une période sans observation.Scénario de démonstration uniquement.

5. Méthode recommandée

Septembre 2026

  • Conserver les cours, l'indice et les volumes observés.
  • Ne pas remplacer les volumes nuls.
  • Forward-filler seulement les données explicitement non cotées.

Jours ouvrés entre deux séances

  • Actions : interpolation du dernier cours connu au prochain cours connu.
  • Obligations : maintien du dernier cours connu, compte tenu de l'illiquidité.
  • OPCVM : interpolation seulement si la périodicité le permet.
  • Indice : interpolation linéaire entre les observations.
  • Volumes : valeur vide ou zéro selon une convention documentée.

Janvier à août 2026

  • Ancrer les prix au premier cours observé de septembre.
  • Utiliser les plus hauts, plus bas et variations annuelles publiés comme repères.
  • Générer une trajectoire progressive et reproductible.
  • Utiliser une graine aléatoire fixe.
  • Marquer chaque valeur comme SIMULATED.
  • Privilégier un prix stable pour les titres très illiquides.

6. Métadonnées à ajouter

Les tables de cotation devraient conserver la provenance de chaque valeur :

data_status VARCHAR(20) NOT NULL DEFAULT 'OBSERVED',
source_date DATE,
interpolation_method VARCHAR(50),
  
Une table dédiée peut également être créée :

  
CREATE TABLE market_data_provenance (
    id BIGSERIAL PRIMARY KEY,
    instrument_code TEXT,
    observation_date DATE NOT NULL,
    data_status TEXT NOT NULL,
    method TEXT,
    source_bulletin TEXT,
    source_date DATE,
    confidence_score NUMERIC(5,2),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

8. Limites des métriques

  
La volatilité, le Sharpe, la VaR, le drawdown, la performance annuelle et les corrélations seront artificiellement influencés par les données simulées.

  
Présentation recommandée: afficher séparément « Performance observée : septembre 2026 » et « Performance démonstrative : janvier à décembre 2026 ». Les rapports COSUMAF doivent utiliser uniquement les valeurs observées, sauf s'ils sont explicitement marqués comme démonstratifs.
